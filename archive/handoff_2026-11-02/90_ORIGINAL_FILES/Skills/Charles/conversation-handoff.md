# Conversation Handoff

建立一份供全新對話使用的**冷啟動包**。它不是聊天紀錄摘要，也不是完整使用者檔案；它只攜帶下一個工作階段避免重做、誤解或遺失所需的最小充分狀態。

若使用者提供參數，把它視為下一個對話的主要目標。若未提供，從目前仍在進行的工作推定最可能的目標，並標示為「推定目標」。

## 1. 鎖定續接邊界

確定：

1. 下一個對話要完成什麼。
2. 目前工作停在哪個狀態。
3. 哪些內容已結案，不應重新展開。
4. 哪些問題仍未決，會決定下一步。
5. 新對話需要哪些檔案、來源或工具才能開始。

同一對話若含多個主題，只攜帶與續接目標直接相關者；其他主題列為刻意排除。

**完成條件：**目標、停止點、未決範圍與排除範圍均明確。

## 2. 執行 next-turn test

檢視目前對話及實際使用過的素材。每項候選資訊都問：

> 新對話若不知道它，是否會重複已完成工作、違反限制、推翻既有決定、重問已回答問題，或無法選擇正確下一步？

只有答案為「是」才納入。優先保留：

- 目前目標與成功條件。
- 已確認事實、決策及其理由。
- 本任務相關的硬限制與偏好。
- 已完成工作及驗證結果。
- 工作假設、未知、風險與阻塞。
- 已排除或失敗的嘗試及其證據。
- 需繼續使用的素材、版本與路徑。
- 下一個可執行動作及必要輸入。

刪除不影響續接的聊天細節、無關個人資料、既有產物的大段複製及未受支持的補全。

**完成條件：**每項納入內容均通過 next-turn test。

## 3. 標記認知狀態

所有會影響下一步的資訊指定一個主要狀態：

- **已確認** — 對話、測試、檔案或可靠來源直接支持。
- **已決定** — 已做出選擇；需保存理由與適用範圍。
- **工作假設** — 用於推進但尚未充分驗證。
- **未決** — 仍需資料、測試或使用者決策。
- **已排除** — 已由具體證據否定。
- **已過時風險** — 可能因日期、版本、價格、政策或情勢改變而需重查。

討論過不等於已決定；合理推論不等於已確認。

**完成條件：**新對話能辨認每項重要資訊的確定程度。

## 4. 引用既有產物

規格、報告、程式碼、試算表、圖片、診斷紀錄或來源整理已存在時：

1. 記錄精確名稱、路徑、Library 位置、connector 識別資訊或可用引用。
2. 簡述內容與新對話何時需要讀取。
3. 只摘錄下一步立即需要、無法由原產物方便取得的內容。
4. 標記版本、日期與是否需刷新。

檔案只存在於 Library 或 connector 時，不虛構 `sandbox:/mnt/data/` 連結。只有已確認存在於執行環境的檔案才能提供 sandbox 路徑。

**完成條件：**每個產物只有一個權威位置，交接檔只提供可解析指標。

## 5. 保存決策與未決佇列

每個會約束後續工作的決策，記錄：

| 欄位 | 內容 |
|---|---|
| Decision | 已選擇什麼 |
| Rationale | 為何如此選擇 |
| Scope | 適用範圍 |
| Reopen trigger | 哪項新證據或條件可重開決策 |

區分硬限制、偏好與暫時工作選擇。只帶入本任務相關的使用者資訊。

把剩餘工作排列為：

1. **目前阻塞點**
2. **下一個決策**
3. **下一個動作**
4. **結果分支**
5. **完成判準**

下一個動作只能有一個，且必須立即可執行，包含輸入與預期產物。不要寫成「繼續研究」或「進一步分析」。

**完成條件：**新對話不必重新規劃便知道第一步，以及何種結果會決定後續。

## 6. 套用相關分支

依續接目標讀取 `/Skills/Charles/conversation-handoff-reference.md` 中相符的分支。只加入該分支要求的狀態，不將整份 reference 複製進交接檔。

**完成條件：**領域特定資訊足以讓對應 skill 接手，且無無關分支內容。

## 7. 建立冷啟動包

檔名使用：

`conversation-handoff-<short-topic>-YYYY-MM-DD.md`

預設存入目前可下載的工作目錄。只有使用者明確要求持久保存時，才上傳至 Library 指定位置。不得覆寫既有交接檔，除非使用者明確要求更新同一文件。

使用以下最小結構；沒有內容的可選段落省略：

```markdown
# Conversation Handoff — [主題]

- **建立時間：** [含時區]
- **下一個對話目標：** [明確目標]
- **目前狀態：** [進行中／受阻／待驗證／已完成待延伸]
- **續接信心：** [高／中／低；依資訊完整度]

## 冷啟動指令
[先讀哪些素材，接著完成什麼。可直接交給新對話。]

## 已確認與已決定
[會約束後續工作的狀態、事實、決策與理由。]

## 使用者限制與偏好
[只列本任務相關者，區分硬限制與偏好。]

## 已完成工作
[產物、測試、查證與驗證；引用既有 artifact。]

## 未決與風險
[工作假設、缺失資料、已過時風險與真正衝突。]

## 已排除與避免重做
[嘗試、結果與排除證據。]

## 下一個動作
[唯一、立即可執行的第一步；含輸入、產物與結果分支。]

## 完成判準
[何時可宣告下一個對話目標完成。]

## 素材索引
[檔案、Library 路徑、來源、版本、日期與用途。]

## 建議 Skills
[skill 名稱、使用時機與順序。]
```

冷啟動指令不得要求新對話重新詢問交接檔已提供的資訊。

**完成條件：**文件已建立、路徑可確認，且所有保留段落直接服務續接目標。

## 8. 執行 cold-start test

假設新 agent 只能看到：

1. 交接檔；
2. 交接檔明確引用的素材；
3. 使用者的一句「接著做」。

確認它能回答：

- 正在完成什麼？
- 工作已到哪裡？
- 哪些事實與決策不可擅改？
- 哪些內容仍未確定？
- 哪些嘗試不應重做？
- 第一個動作是什麼？
- 要讀哪些素材、用哪些 skills？
- 什麼條件代表完成？

若任何答案需要重讀舊對話，補足交接；若內容只是有趣但不影響工作，刪除。

**完成條件：**新對話只靠冷啟動包與引用素材即可開始第一個動作，不必重問已知資訊。

## 敏感資訊

採最少必要原則。移除憑證、秘密、完整身份識別資料及與任務無關的私人資訊。臨床資料去識別化；若精確日期、地點或罕見特徵會增加再識別風險，改用完成工作所需的較粗粒度描述。

## Response contract

完成時只提供：

1. 交接主題與下一個對話目標。
2. 已確認的檔案位置或下載連結。
3. 一句使用方式。
4. 若存在，一項仍可能阻礙續接的重大缺口。

不要在聊天回覆中再次貼出完整交接文件。

## Failure modes

- **Transcript compression** — 按時間重述聊天。改用 next-turn test。
- **Profile dump** — 帶入完整使用者記憶。只保存本任務相關限制。
- **Artifact duplication** — 複製既有產物。改為精確引用。
- **Decision flattening** — 遺失理由與重開條件。補 decision record。
- **Certainty laundering** — 將假設或推論寫成已確認。恢復狀態標籤。
- **Stale-state carryover** — 將動態資訊當永久事實。標記截止時間與刷新需求。
- **Dead-end handoff** — 有背景但沒有唯一下一步。建立可執行動作。
- **Task-list dumping** — 忽略阻塞與分支。建立未決佇列。
- **Sensitive overcapture** — 保存非必要識別資訊或秘密。最小化並去識別化。
- **False sandbox link** — 對 Library 或 connector 檔案虛構下載路徑。只連結已確認檔案。
- **Cold-start failure** — 新對話仍需重問或翻舊聊天。補足必要狀態後重測。

## Final completion criterion

只有在 cold-start test 通過、敏感資訊已最小化、既有產物未被重複、且唯一下一個動作明確時，才完成 conversation handoff。
