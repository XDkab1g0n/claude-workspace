# 音樂評分 Ledger

更新日期：2026-09-18

## 評分規則

### 1. 評分對象

預設評的是**指定版本的完整成品**，不是只評作曲稿，也不是只評歷史地位。  
因此同一首歌的原版、翻唱、現場、重製、Long / Extended 版可以有不同分數。

若某次明確只討論 songwriting、composition、演唱、現場表現等單一面向，才另外標示該面向分數，不與完整作品總分混用。

### 2. 核心判準

評分的核心問題只有一個：

> **這個版本還有沒有一個具體、值得做，而且做了之後會讓成品更好的修改？**

這個「修改」可以來自任何層面，例如：

- melody / hook
- harmony
- rhythm / groove
- form / section architecture
- arrangement / orchestration
- sound design
- vocal / instrumental performance
- Vocaloid tuning
- lyrics / narrative
- dynamic architecture / climax / payoff
- production / mix / mastering
- concept execution
- 各元素之間的 integration
- identity / irreplaceability

不是每首歌都必須在所有面向同樣強；要看作品自己的目標。  
例如極簡 pop 不會因為和聲不複雜而被扣分，高密度音遊曲也不會因為資訊量大就自動加分。

### 3. 10/10 的定義

**10/10 = 我認為這個版本已經沒什麼值得改。**

也就是在主動嘗試提出替代方案之後，仍然找不到一個**有意義、可執行，而且預期會讓作品更好**的修改。

這不代表作品客觀完美，也不代表所有人都應該喜歡；更不代表所有 10/10 彼此同等。

**10/10 之間本來就可以有高下。**  
只是進入這個區間後，差異往往來自不同作品在不同維度上的峰值，很難再用 10.1、10.2 之類的假精確數字表示。

10 分也**不要求稀有**。如果有很多作品都真的沒有值得改的地方，就可以有很多 10/10；不能因為「滿分太多」而人工降分。

### 4. 9.x 的大致含義

- **9.9**：幾乎完整，但仍能指出至少一個很小、卻是真實且值得做的改善。
- **9.7–9.8**：極強作品；已有少量可感知的不足、冗餘、失衡或可替代之處，但不傷核心價值。
- **9.5–9.6**：非常優秀；亮點明確，但若干段落、材料、製作或整合仍有實質改善空間。
- **9.0–9.4**：強作；整體成立，但缺點、可替代性或完成度差距已經相對明顯。
- **8.x**：好作品，但優缺點都明顯；離頂級完成度還有一段距離。
- **7.x 以下**：依序代表更多結構性、表演、製作或概念執行問題。

分數不是平均公式。  
一首作品可以某些子項只有 9.4，卻因為那個「不完美」正是其 identity 的必要部分而整體仍是 10；反過來，也可能每項都很漂亮，但整體缺乏不可替代性而不到 10。

### 5. 「限制」與「缺點」要分開

不是所有限制都值得扣分。

例如：

- 老錄音的年代感
- 故意粗糙的 vocal
- 極簡和聲
- 高密度編曲
- 短篇幅
- 特定類型的重複性

只有在我認為**改掉它真的會讓成品更好，而且不會破壞作品原本的 identity / purpose**時，才算值得扣分的缺點。

因此不能用「更乾淨、更現代、更複雜、更長」直接等同「更好」。

### 6. 歷史地位與影響力

歷史地位、文化影響、先驅性、榜單成績、作品人氣都可以討論，但**不能直接換成作品分數**。

一首歷史上很重要的歌，可以只有 9.5；  
一首影響力很小的歌，也完全可以是 10。

歷史背景只在它能幫助理解作品本身的設計、語境或技術選擇時參與分析。

### 7. 原作、翻唱、現場與改編

每個版本都獨立評。

翻唱或改編不因「唱得更難」「製作更大」「聲音更漂亮」就自動高於原版；要看它是否真的產生新的價值，或只是把原本已經成立的東西換一種表面。

現場版本則把**現場本身視為最終成品**：演唱、樂手、編排、現場張力、錄音呈現都一起算。

### 8. 故事／IP Context

如果作品明確為動畫、遊戲、電影或角色敘事服務，可以評它與原作情境的整合度；但不能因為「我喜歡這個角色／劇情」就直接加分。

若作品在 standalone 與 context-dependent 的評價差異很大，應分開標示，例如：

- standalone：9.9
- 作為作品 finale / narrative payoff：10

### 9. 版本長度

Game size、Short ver.、Long / Extended / Uncut 等版本分開看。

若短版本身已經完整，它可以獨立得到 10。  
若真正的結構完成度只在 Long / Extended 版出現，ledger 只保留那個完整版本，避免同一首歌重複佔位。

### 10. 最後判斷方式

評到最高分區時，不問：

> 「它夠不夠資格成為經典？」  
> 「10 分是不是太多？」  
> 「別人會不會覺得我給太高？」

只問：

> **如果現在要我真的動手改這個版本，我有沒有一個確定值得改、而且改了會更好的地方？**

沒有，就是 **10/10**。  
有，就依那個問題的大小與重要性往下扣。
