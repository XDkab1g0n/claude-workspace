# Device Diagnostics

用可重複的**故障隔離**流程處理裝置問題。先建立能穩定觀察症狀的診斷迴圈，再透過對照組、單變量測試與可否證假設定位故障層；修復只是最後一步。

涉及產品規格、韌體、驅動、相容性、已知問題或近期更新時，使用 `source-backed-analysis` 查證當前資料。若使用者質疑先前診斷，使用 `independent-reassessment` 作為外層流程。

## 0. 安全分流

先辨認是否存在需要停止一般測試的風險：

- 電池膨脹、冒煙、異味、火花、液體侵入或異常高溫。
- 市電、高電壓、裸露導體、損壞電源供應器或不明接地問題。
- 耳機或喇叭可能突然輸出高音量、直流、爆音或回授。
- 測試可能造成資料遺失、裝置鎖定、保固失效、網路中斷或安全設定暴露。

有立即危險時，先斷電、隔離或交由合格維修人員處理。高風險但可測試的情況，先說明風險、備份與回復方法，再執行可逆步驟。

**完成條件：**已確認一般診斷可安全進行，或已明確停止並給出安全處置。

## 1. 建立症狀契約

把「不能用」「很慢」「連不到」「有雜音」改寫成可觀察的故障條件：

1. **觸發條件** — 做什麼後出現。
2. **精確症狀** — 螢幕、指示燈、錯誤碼、聲音、速度、延遲、掉線或溫度實際如何。
3. **預期結果** — 正常時應該發生什麼。
4. **範圍** — 哪些裝置、帳號、頻段、輸入、輸出、應用或位置受影響。
5. **時間線** — 從何時開始；之前做過哪些更新、換線、搬動、斷電或設定變更。
6. **頻率** — 必現、間歇、特定負載或特定時間才發生。

先區分故障層級，不把不同症狀混成一個問題：

- 偵測／發現：看不到 SSID、藍牙裝置、USB 裝置或輸入來源。
- 配對／關聯／認證：看得到但連不上、密碼或憑證失敗。
- 設定／位址：已連接但未取得 IP、音訊格式、顯示模式或權限不正確。
- 傳輸／路徑：區域連線成立，但封包、訊號、影像或聲音無法抵達目的端。
- 服務／應用：底層連線正常，特定網站、App、遊戲或串流失敗。
- 效能／穩定：可用但慢、延遲、斷續、降頻、爆音或不定期重啟。
- 電源／熱／物理：無法開機、充電、待機喚醒，或受接點、線材、溫度與機械結構影響。

**完成條件：**症狀可用一句 pass/fail 命題描述，且故障被放在最窄的已知層級。

## 2. 凍結狀態向量

診斷前記錄足以重現的狀態：

- 裝置品牌、完整型號、硬體版本與區域版本。
- OS、韌體、驅動、App 版本及最近更新時間。
- 拓撲與訊號路徑：來源 → 中介裝置 → 目的端。
- 連接方式、線材、轉接器、Hub、Port、頻段、協定與電源來源。
- 相關設定、模式、輸入輸出、權限、增益、電源管理與自動切換功能。
- 位置、距離、遮蔽物、溫度、負載、電量與其他環境條件。
- 已嘗試操作及其結果。

測試過程中每次改動都記錄「原值 → 新值 → 結果」，避免無法回到基線。

**完成條件：**另一個人能依記錄重建問題環境，且後續測試不會把未知變更混入結果。

## 3. 建立緊密診斷迴圈

建立一個能反覆執行的最小流程：

- 一個明確觸發動作。
- 一個直接觀察值或量測值。
- 一個 pass/fail 門檻。
- 一個回到起始狀態的方法。
- 一次執行所需時間與間歇問題的重現率。

優先使用能量測而非只靠感覺的訊號，例如錯誤碼、事件紀錄、連線狀態、IP／DNS 結果、RSSI、封包遺失、吞吐量、延遲、溫度、功耗、充電協定、音訊通道交換或已知測試檔。

對間歇問題，不要求一次必現；提高並量化重現率。固定位置、負載、時間、溫度與步驟，連續執行足夠次數，使變化可比較。

無法建立迴圈時，明確列出缺少的觀測能力：需要螢幕錄影、日誌、錯誤碼、測量工具、另一條線、另一個裝置、現場操作或維修檢測。沒有可觀察訊號時，不宣稱已定位根因。

**完成條件：**已有一個實際執行過、能捕捉使用者精確症狀的快速迴圈，或明確記錄目前缺少什麼才能建立。

## 4. 建立對照矩陣並最小化

至少建立一個已知正常的對照。依問題選擇：

- 同一裝置換已知正常的線、Port、充電器、網路、輸入或輸出。
- 同一路徑換另一台已知正常裝置。
- 同一裝置在另一個位置、頻段、帳號、App、OS 使用者或電源來源測試。
- 問題配置與預設／安全模式／最小拓撲比較。

一次只改一個會影響結論的變數。每次測試後立即重跑診斷迴圈，再決定下一步。把不影響症狀的元件與設定從重現條件移除，直到剩下最小故障拓撲。

若兩個變數必須成組改動才能測試，標記為複合測試；其結果不能歸因到其中任一個單獨變數。

**完成條件：**已知至少一個 pass 對照與一個 fail 條件；最小故障拓撲中的每個剩餘元素都可能影響症狀。

## 5. 排列可否證假設

在大規模改設定、重置或送修前，建立 3–5 個假設。每個假設記錄：

| 欄位 | 內容 |
|---|---|
| Mechanism | 它如何造成精確症狀 |
| Prediction | 若為真，哪個觀察應改變 |
| Discriminator | 哪個低成本測試能區分它與其他假設 |
| Risk and reversibility | 測試風險、資料影響與回復方式 |
| Result | 實際結果 |
| Update | 提高、降低或排除該假設 |

假設按「先驗合理性 × 區分力 ÷ 成本與風險」排序。已知問題、產品限制與相容性主張需要用 `source-backed-analysis` 查證，不能把論壇共識或記憶當作根因證據。

**完成條件：**每個活躍假設都有機制、可觀察預測與區分測試，不存在只靠印象的原因猜測。

## 6. 執行資訊增益最高的測試

優先順序：

1. 可逆、低風險、能明確區分多個假設的測試。
2. 不需改永久設定的觀測與通道交換。
3. 小範圍暫時設定變更。
4. 驅動／韌體回復、網路重設、App 重裝等中成本措施。
5. 工廠重置、拆機、刷寫、購買替換品或送修等高成本措施。

每次測試只回答一個問題。先寫下預測，再執行；結果不符時更新假設，而不是替原假設補充無限例外。

依問題類型讀取 `/Skills/Charles/device-diagnostics-reference.md` 的對應分支。分支清單是測試候選，不是要全部依序執行；只選能區分目前假設的下一步。

**完成條件：**每個測試都對應一項預測，結果已更新假設排序，且未用高破壞性操作取代尚未完成的低風險隔離。

## 7. 修復並驗證

根因獲得足夠支持後，採用能解決根因的最小修復，而非僅掩蓋症狀。修復後：

1. 重跑最小診斷迴圈，確認轉為 pass。
2. 重跑原始完整情境，確認使用者實際問題消失。
3. 測試相鄰功能，確認沒有造成新的連線、音訊、效能、耗電或安全問題。
4. 還原為診斷而做、但不屬於修復的暫時變更。
5. 記錄根因、證據、有效修復與被排除的常見替代解釋。

若只找到 workaround，明確標示為暫時繞過，說明未解根因、代價與觸發失效的條件。

**完成條件：**最小與原始情境均已驗證，永久變更與暫時變更已分開，根因或未解狀態有證據支持。

## 8. 停止與升級

下列情況停止遠端診斷並升級：

- 需要危險的電氣、電池、拆機或高音量測試。
- 缺少必要工具或替代件，無法區分剩餘假設。
- 證據集中指向主板、電源、儲存、顯示面板、無線模組、端子等硬體故障。
- 保固、資料價值或停機成本高於繼續嘗試的收益。
- 製造商診斷、序號保固、維修模式或實體量測才能進一步判定。

升級時提供：精確症狀、最小重現、型號與版本、已完成測試、pass/fail 對照、最可能故障層、尚待區分的假設與避免重做的步驟。

**完成條件：**繼續測試與升級之間已有明確決策，且維修端取得可直接接手的診斷摘要。

## 互動契約

除非使用者要求完整檢查表，預設一次提出**一個**下一步測試，格式如下：

```markdown
**目前定位：** [最窄故障層級；信心高／中／低。]

**下一個測試：** [一個具體、可逆的操作。]

**它在區分：** [假設 A] 與 [假設 B]。

**結果解讀：**
- 若 [結果 1]：下一步與推論。
- 若 [結果 2]：下一步與推論。
```

取得結果後再選下一個測試，不預先傾倒大量互相依賴的步驟。若使用者無法即時操作，才提供按分支排列、每步都有停止條件的檢查表。

完成診斷時使用：

```markdown
**診斷結論：** [根因／最可能故障層／仍未決。] **信心：高／中／低。**

## 證據
[最小重現、對照測試與排除結果。]

## 修復
[永久修復或 workaround，以及回復方法。]

## 驗證與剩餘風險
[原始情境是否通過、尚未解的不確定性與何時應送修。]
```

## Failure modes

- **Shotgun troubleshooting** — 一次切換多個設定，得到成功但失去因果資訊。回到基線後單變量重測。
- **Reset-first** — 在定位前工廠重置、重裝或清除網路，破壞原始證據。先建立迴圈與對照。
- **Layer collapse** — 把「看不到」「連不上」「無網路」「特定 App 失敗」視為同一故障。先分層。
- **Reboot proof** — 重開後暫時正常便宣布根因。把重開視為測試結果，繼續找出被重置的狀態。
- **Known-issue anchoring** — 找到相似網路貼文就停止診斷。必須證明型號、版本、條件與症狀吻合。
- **Control contamination** — 對照組同時改了多個路徑或環境條件。標記為複合測試，建立更乾淨對照。
- **Workaround laundering** — 繞過問題後把它描述成根因修復。分開記錄。
- **Destructive escalation** — 低風險隔離尚未完成便進入刷機、拆機、購買或重置。依風險階梯回退。
- **Unmeasured performance** — 只用「感覺慢／音質差／不穩」比較。定義指標、場景與基線。
- **Success without verification** — 一次成功便結案。重跑最小與原始情境並確認相鄰功能。

## Final completion criterion

所有階段的完成條件與互動契約均成立後，才宣告問題已定位、已修復或應升級處理。
